# 통합 설계 결정 기록

## 브랜치 통합

- `origin/main`: 회원, 학습방, WebSocket 기능을 제공했지만 SQLite와 별도 모델 계층을 사용했다.
- `origin/AITraining`: `main`보다 한 커밋 앞서며 고1 수학 JSON, Chroma 인덱서, 검색 CLI를 추가했다.
- `origin/front`: 별도 Git 이력의 React/Vite 정적 UI였다.
- `local-mysql-snapshot`: 통합 전 로컬 MySQL 스키마와 문서를 보존한다.
- `origin/main`: 백엔드, AITraining 자료 처리, 프런트, MySQL 통합 코드의 현재 기준이다.

## 핵심 결정

1. 운영 데이터 저장소를 MySQL 하나로 통일했다.
2. 대형 임베딩 모델은 기본 의존성에서 제외했다.
3. AITraining JSON을 앱 시작 시 MySQL 문서/청크로 멱등 인덱싱한다.
4. 기본 모드는 네트워크 없이 동작하는 검색·규칙 기반 튜터다.
5. 생성형 응답이 필요하면 같은 API에서 OpenAI 또는 Ollama를 선택적으로 호출한다.
6. 프런트는 JWT를 저장하고 모든 주요 화면에서 실제 REST API를 사용한다.
7. 테스트는 SQLite로 빠르게 격리하고 실제 MySQL은 별도 스모크 테스트로 확인한다.
8. 운영 그룹 채팅은 JWT와 학습방 권한을 확인하고 MySQL에 영속화한다.
9. Railway의 여러 백엔드 인스턴스 사이 WebSocket 이벤트는 Redis Pub/Sub으로 전달한다.

## 데이터 흐름

1. 사용자가 가입하고 JWT를 발급받는다.
2. 학습방을 만들거나 초대 코드로 참여한다.
3. 주제를 선택해 학습 세션을 시작한다.
4. RAG 서비스가 2022 원본 또는 2022 성취기준 매핑이 있는 선택 과목 청크를 찾고, 자료가 없으면 일반 첫 질문을 제시한다.
5. 사용자의 설명을 저장하고 핵심어·설명 충실도를 평가한다.
6. 관련 근거와 후속 질문을 AI 메시지로 저장한다.
7. 종료 시 학습 기록과 정리노트를 생성한다.
8. 같은 RAG 자료로 복습 퀴즈를 생성하고 시도를 기록한다.

## 알려진 경계

- 로컬 기본 모드의 점수는 교육적으로 검증된 모델 점수가 아니라 휴리스틱이다.
- Ollama가 중단되면 기본 로컬 응답으로 자동 폴백한다.
- API는 선택적 Chroma 의미 검색을 우선 사용하고 사용할 수 없으면 가벼운 어휘 관련도 검색으로 전환한다. 두 검색 모두 `RAG_CURRICULUM_YEAR=2022` 정렬 정책을 공유한다.
- Redis가 없으면 WebSocket 채팅은 단일 백엔드 인스턴스 안에서만 브로드캐스트된다.
- Railway 배포는 관리형 MySQL·Redis, 공개 Backend·Frontend 네 서비스 구성을 전제로 한다.
