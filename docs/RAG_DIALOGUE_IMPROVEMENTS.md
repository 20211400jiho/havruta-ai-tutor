# 검색 재정렬과 대화 상태 관리

작성: 2026-09-09. 로컬 구현 기록이며 GitHub push / Railway 배포 기록이 아니다.

2026-09-11 후속 보완: [1주차 피드백 대응](CAPSTONE_WEEK1_RESPONSE.md). 학습목표/종료 결과/노트 연결을 추가했고,
새 개인 대화의 규칙 기반 숫자 평가를 제거했다. 아래의 56개 테스트·로컬 상태는 최초 구현 시점의 기록이다.
최신 배포 검증은 [배포 기록](RELEASE_VALIDATION.md)을 확인한다.

## 1. 변경 범위

```text
학생 답변 + DB에 저장된 최신 대화 상태
  → 응답 유형 판별(설명/힌트 요청/맞장구/질문)
  → 주제 + 유지할 핵심 질문으로 검색 질의 구성
  → 기존 과목·학년·단원 범위에서 후보 15개 검색
  → 중복 제거 + 재정렬 → 최종 3개
  → OpenAI 구조화 응답(설명/다음 질문/잠정 평가/인용/출처)
  → 서버가 단계 전환 조건 확인
  → AI 메시지와 대화 상태를 같은 DB 트랜잭션으로 저장
  → 재접속 시 최신 메시지의 상태 복원
```

초기 질문 등 기존 검색 호출은 요청한 top_k를 유지한다. 일반 채팅은 최종 3개다.

## 2. 재정렬

- 구현: `app/rag/reranker.py`, 연결: `app/rag/retriever.py`.
- 기본값은 **BM25 + 순위 결합(RRF)**. Cross-Encoder를 기본 적용했다고 표현하지 않는다.
- 후보 문서 내 단어 빈도, 문서 빈도, 길이를 사용하는 BM25로 재평가한다.
- 한글 어절 및 글자 bigram을 함께 사용한다. 형태소 분석기나 학습된 한국어 의미 평가기는 아니다.
- 기존 검색 순위와 BM25 순위를 `0.35/(60+기존 순위) + 0.65/(60+BM25 순위)`로 결합한다.
- 공백 정규화 후 같은 내용의 문서를 제거한다. 의미상 유사한 모든 중복을 제거하는 것은 아니다.
- 기존 의미·어휘 검색 점수는 원본 그대로 보존하고, 재정렬 방식/전후 순위/별도 점수는 metadata에 기록한다.
- 어떤 점수도 정답 확률이 아니다. 학생 화면의 관련도 퍼센트를 제거하고 참고 자료와 재정렬 방식을 표시한다.

설정 (`.env` 또는 배포 서비스 환경변수):

```dotenv
RAG_RERANKER=bm25
RAG_RERANK_CANDIDATES=15
RAG_RERANK_MODEL=
```

`off`로 기존 검색 순위를 사용할 수 있다. `cross_encoder` 선택 시 sentence-transformers의 CrossEncoder로
질문·문서 쌍을 재평가한다. `RAG_RERANK_MODEL`에는 검토한 다국어 모델의 로컬 경로나 캐시된 모델 ID를 지정한다.
별도 모델은 이번 작업에서 다운로드하거나 배포하지 않았다. CPU, batch 8, max_length 512이며 런타임 다운로드는 금지한다.
모델 부재/로드 실패/잘못된 점수/추론 실패 시 BM25로 대체하고 `rerank_fallback`에 기록한다.
실패한 모델 로드는 프로세스 내 캐시되므로 모델 준비 후 서비스를 재시작한다.

제약: 후보에 필요한 자료가 없으면 재정렬로 복구할 수 없다. BM25는 동의어와 부정문 처리에 한계가 있다.
후보 검색 확대와 Cross-Encoder는 지연·메모리 사용을 늘릴 수 있으므로 배포 환경에서 별도 측정해야 한다.

## 3. 대화 상태

구현: `app/rag/dialogue.py`, `app/rag/tutor.py`, `app/routers/sessions.py`.

기존 `messages.response_meta_json`에 버전이 있는 `dialogue_state` 스냅샷을 저장한다.
새 테이블/컬럼이나 마이그레이션은 필요 없다. 원본 대화와 기존 학습 데이터는 삭제하지 않는다.

| 필드 | 역할 |
| --- | --- |
| stage | 현재 단계 |
| focus_question | 힌트 대화에서도 유지할 핵심 질문 |
| last_question | 실제로 화면에 표시한 직전 후속 질문 |
| hint_count | 현재 개념에서 요청한 힌트 횟수 |
| last_intent | 답변·질문·힌트·맞장구 구분 |
| misconception | 아직 남은 오개념에 대한 잠정 기록 |
| evidence | 단계 전환에 사용한 학생 인용·출처·판단 이유, 최대 5개 |
| transition_reason | 단계 유지/전환 이유 |

이전의 발언 횟수 기반 단계 상승을 제거했다. 이제 다음 조건이 모두 있어야 한 단계 진행한다.

1. 서버가 학생 입력을 설명/답변으로 판별했다.
2. AI가 현재 핵심 질문에 대해 `understood`로 판단했다.
3. 근거 인용이 실제 최신 학생 답변에 포함된다.
4. AI가 제시한 출처 ID가 현재 검색 결과에 존재하며 비어 있지 않다.

이는 **잠정적인 AI 이해 판단의 형식적 검증**이다. 인용과 출처 ID 존재 확인만으로 답변의 사실성,
인용의 적절성, 학생의 완전한 숙달까지 검증한 것은 아니다. `verified_by_human=false`로 기록한다.
힌트·맞장구·학생 질문에는 단계 상승을 금지한다. 자료가 없거나 AI가 실패한 경우도 단계를 유지한다.
이때 학생은 계속 질문하거나 기존 학습 종료 기능을 사용할 수 있다.

AI에는 다음을 명시한다: 학생 질문에 먼저 답하기, 모르면 같은 개념에서 설명하기,
두 번째 이후 힌트에는 직접 설명과 선택형 예시 사용하기, 짧은 답변을 길이만으로 감점하지 않기,
힌트 질문에 답했어도 핵심 질문이 해결되지 않았다면 심화하지 않기.
이러한 자연어 응답 행동은 지침이며 모든 생성에서 준수한다고 보장하지 않는다.

OpenAI 공식 Structured Outputs 방식을 사용해 설명·질문·평가를 함께 받는다.
추가 평가용 API 호출은 만들지 않았다. 구조화 응답은 출력 예산을 기존 설정과 1200토큰 중 큰 값으로 잡는다.
따라서 기존 700토큰 설정 대비 최대 출력 비용이 증가할 수 있다. 모델 설정 자체는 변경하지 않았다.
형식 오류, 중단된 출력, 거부로 인한 출력 부재는 규칙 기반 폴백으로 처리하며 원시 JSON을 학생에게 표시하지 않는다.

이전 세션에 상태가 없으면 가장 최근 AI 질문과 기존 단계로 시작한다. 이전 발언 수로 숙달을 추정하지 않는다.
새 구조화 응답의 학생 평가는 숫자 대신 잠정 평가로 표시한다. 기존 규칙 평가 코드는 호환성을 위해 남아 있지만
단계 전환에는 사용하지 않는다. 정리노트·대시보드의 과거 점수가 검증된 학습효과가 되는 것은 아니다.

## 4. 검증과 측정

로컬 실행 결과: pytest 56개 통과, 프론트 lint/build 통과. 테스트 건수는 품질 향상률이 아니다.

```bash
.venv/bin/python -m pytest -q
npm --prefix web run lint
npm --prefix web run build
```

테스트는 재정렬 순서/중복/범위 필터/모델 장애, 반복 힌트, 맞장구와 질문의 단계 유지,
짧은 답변의 인용 기반 진행, 틀린 긴 답변 유지, 잘못된 출처/인용 차단,
DB 저장·이어하기·세션 간 분리, 구조화 출력 오류와 중단 처리를 검증한다.
AI와 Cross-Encoder를 대체한 테스트는 **실제 모델의 답변 품질을 검증한 실험이 아니다**.
프론트 변경은 lint/build로 검사했으며 실제 브라우저 화면과 운영 AI 대화는 이번 작업에서 검증하지 않았다.

재정렬 비교 도구:

```bash
.venv/bin/python -m scripts.evaluate_reranking /path/to/labelled_cases.json --top-k 3
```

입력 형식(아래는 형식 설명용 예시이며 평가 결과가 아님):

```json
[
  {
    "id": "science-001",
    "query": "여러 조직이 모이면 무엇이 되나요?",
    "relevant_source_ids": ["source-b"],
    "candidates": [
      {"source_id": "source-a", "content": "식물의 광합성 설명", "score": 0.8},
      {"source_id": "source-b", "content": "여러 조직이 모여 특정 기능을 수행하는 기관을 이룬다.", "score": 0.7}
    ]
  }
]
```

`candidates`는 실제 기존 검색 순서대로 수집하고 사람이 관련 자료 ID를 판정해야 한다.
후보 고정 전후 Precision@K, Hit@K, MRR@K와 재정렬 자체 시간을 출력한다.
K개 미만을 반환해도 Precision 분모는 K로 유지한다. 이 도구는 후보 재생 실험이며 전체 검색/생성 지연은 측정하지 않는다.
기존 `evaluate_rag.py`는 성취기준 검색 무결성 검사이므로 재정렬 품질 평가로 혼동하지 않는다.

실제 성과 보고 전 필요한 후속 검증:

- 튜닝용과 분리한 평가셋, 과목별 결과 및 실패 사례.
- 동일 후보/동일 모델 설정으로 전후 비교. 전체 시스템 비교 시 후보 확대와 재정렬 효과도 분리.
- 실제 다중 턴 대화에서 맥락 이탈의 정의를 고정하고 사람 검토로 판정.
- Ragas를 사용하려면 별도 도입·평가가 필요하다. 현재 Ragas 평가와 환각률 측정은 하지 않았다.
- 이번 구현으로 `68% → 89%`나 `환각 15% 감소`를 달성했다고 주장하지 않는다.

## 5. 배포 및 복구

이번 작업은 로컬 구현이다. 별도 push/배포 요청 전에는 운영 서비스를 변경하지 않는다.
배포 시 기존 루트 Docker/Railway 설정을 그대로 사용하며 기본 BM25는 새 모델 파일이 필요 없다.
이전 버전으로 코드를 복구해도 새 대화 상태는 기존 JSON의 추가 필드이므로 DB 구조 복구는 필요 없다.
Cross-Encoder 선택 시 사전에 모델 캐시·라이선스·메모리/지연을 확인한다.
